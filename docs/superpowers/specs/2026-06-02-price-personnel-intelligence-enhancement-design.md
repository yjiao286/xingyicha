# 报价分析 & 人员比对智能增强 — 设计文档

**日期**: 2026-06-02
**状态**: 已确认

## 目标

提升报价分析和人员交叉比对两个模块对各种格式、排版和命名撰写方式的适应能力，在保证准确率的前提下提高提取成功率。

## 设计原则

- **渐进增强**：在现有代码基础上扩展，不破坏已验证的逻辑
- **多通道提取**：每条通道覆盖一类格式，取置信度最高的结果
- **章节限定**：人员提取仅在特定章节进行，避免全文档扫描引入噪声
- **分层比对**：精确→模糊→辅助证据，逐层降低误报

## 一、报价分析增强

### 1.1 多通道总价提取

替代当前单一正则模式链，建立提取通道管道：

| 优先级 | 通道 | 覆盖格式 | 置信度 |
|--------|------|---------|--------|
| 1 | 符号通道 | `￥`/`¥`/`CNY`/`RMB` + 数字 | 0.95 |
| 2 | 标签通道 | `{总价/报价/金额/人民币/小写}[：:]` + 数字 | 0.90 |
| 3 | 表格通道 | "开标一览"/"报价表"区域的行解析 | 0.85 |
| 4 | 上下文通道 | "合计"/"总计"附近的大数值 | 0.70 |
| 5 | 单位通道 | `万元`/`亿元`/`亿`/`万` 后缀解析 | 0.80 |

`_parse_amount()` 增强：
- 支持 `亿元`（×100,000,000）
- 支持中文大写数字 → 阿拉伯数字转换
- 支持价格区间（取平均值）
- 更健壮的数字清理（含全角数字）

### 1.2 智能分项报价表解析（`_parse_pdf_bid_table` 重写）

**章节发现增强**：
关键词集从单一 `分项报价表` 扩展为：
`[分项报价, 报价明细, 价格表, 开标一览, 报价清单, 费用明细, 价格清单, 投标报价, 价格构成, 设备清单, 费用清单]`

**列含义动态推断**（不硬编码列序）：
- 序号列：1-99 整数，单调递增
- 名称列：含中文字符比例最高
- 数量列：1-999 小整数
- 单价列：中等数值
- 总价列：最大数值
- 税率列：1-30 或百分比格式

**合并单元格处理**：
- 检测某行缺失名称列时，继承上一行的名称

### 1.3 通用成本明细提取

去掉硬编码的10个国防科技类别名，改为通用模式：
- 在任何区域寻找 `{中文名}` + `{大数字(>=100)}` 的行
- 中文名长度 2-20 字，包含"费"字优先级高
- 不匹配表格序号行、不匹配纯数字行

### 1.4 分项比对增强（`_build_sub_item_comparison`）

- 归一化增强：去括号内容、标点、空白、全角→半角
- 双算法匹配：LCS（保留）+ Jaccard 2-gram 相似度
- 匹配阈值：exact name match OR (len>=8 AND (LCS>=12 OR jaccard>=0.6))
- 价格差异显示百分比

## 二、人员比对增强

### 2.1 章节限定姓名提取

**识别的章节边界**（通过标题关键字）：

| 章节 | 关键词 | 角色 |
|------|--------|------|
| 授权委托书 | `授权委托书`, `法定代表人授权书`, `法人授权` | legal_rep, authorized_rep |
| 法定代表人身份证明 | `法定代表人身份证明`, `法人代表证明`, `单位负责人证明` | legal_rep |
| 项目管理机构/人员表 | `项目管理机构`, `项目组`, `主要人员`, `项目成员`, `拟投入人员` | project_manager, tech_lead, team_member |
| 资格审查/资质 | `资格审查`, `投标人基本情况`, `企业概况` | bid_contact |
| 签章/签字页 | `签字`, `盖章`, `签章`, `法定代表人或其委托代理人` | signatory |
| 封面/投标函 | `投标函`, `投标书`, `致：` | legal_rep, authorized_rep |

**姓名提取方法**（在限定的章节内）：
- 表格行：识别姓名/职务/身份证/电话列
- 标签行：`姓名[：:]` / `法定代表人[：:]` / `项目经理[：:]` 等
- 签名上下文：签章附近的姓名

### 2.2 角色标签推断（8种）

| 标签 | 推断条件 |
|------|---------|
| `legal_rep` | 附近有"法定代表人"/"法人代表"/"单位负责人" |
| `authorized_rep` | 附近有"授权代表"/"委托代理人"/"被授权人"/"代理人" |
| `project_manager` | 附近有"项目经理"/"项目负责人" |
| `tech_lead` | 附近有"技术负责人"/"技术总监"/"总工程师" |
| `bid_contact` | 附近有"联系人"/且在同一行有电话/邮箱 |
| `team_member` | 在人员表中且无上述角色标记 |
| `signatory` | 在签章区域附近 |
| `other` | 无法推断但确认为姓名 |

### 2.3 姓名归一化

- 去前缀：`我`、`本人`、`委托`、`授权`
- 去后缀标签：`（签字）`、`(盖章)`、`（项目经理）`等
- 跨行修复：预先合并 `{姓}\s*\n\s*{名}` 模式
- 同文档去重：同名+同角色→仅保留一次

### 2.4 分层交叉比对

```
Layer 1: 精确匹配（同名+同角色）        → severity: high
Layer 2: 同名异角（同名但不同角色）      → severity: medium  
Layer 3: 辅助证据（身份证号/电话匹配）   → severity: critical/high
```

| 比对项 | 来源 | 严重程度 |
|--------|------|---------|
| 同一姓名出现在≥2份标书 | 全量姓名集合交集 | high |
| 同一电话出现在≥2份标书 | 人员联系信息 | high |
| 同一身份证号出现在≥2份标书 | 人员身份信息 | critical |
| 授权代表是另一标书文档创建者 | personnel vs metadata | high |
| 人员重叠率 > 阈值 | 交集/并集 | medium |

### 2.5 数据结构增强

```python
  'legal_rep': '...',

```

## 三、实施范围

### 修改文件
- `app.py`：主要修改
  - `extract_prices()` — 多通道总价提取
  - `_extract_structured_items()` — 增强章节发现 + 通用成本提取
  - `_parse_pdf_bid_table()` — 重写为动态列推断
  - `_build_sub_item_comparison()` — 双算法匹配
  - `extract_personnel()` — 章节限定姓名提取 + 角色推断
  - `run_full_analysis()` — 增强 personnel 交叉比对逻辑
  - `_parse_amount()` — 增强数字解析

### 不修改
- `templates/index.html` — 前端无需改动（结果结构向下兼容）
- `static/css/style.css`
- `static/js/main.js`
- 其他分析模块（元数据、文本相似度、文档结构）

### 向后兼容
- 所有新增字段为可选字段
- 现有字段 `legal_rep`, `authorized_rep` 保持原有提取逻辑不变（作为通道之一）

## 四、验证方法

1. 抽取当前已知失败案例的文本片段，验证新提取器能成功提取
2. 构造边界测试用例（各种价格标注格式、不同表格布局、不同人员章节格式）
3. 与现有提取结果对比，确保无回归
4. 运行 Flask 应用进行端到端测试
